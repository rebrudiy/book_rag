# Живой Chromium: русский учебный справочник

`scripts/browser_wikibooks.py` проверяет уже импортированный
`ruwikibooks-regex-266423` в работающем приложении. Он не вызывает acquisition или
ingest, не подменяет ответы API, не создаёт заметки и не отправляет запросы
изменения библиотеки. Наблюдаемые browser requests разрешены только GET/HEAD;
неожиданный метод изменения делает проверку неуспешной.

Из корня проекта, после запуска полной библиотеки на порту 8001:

```sh
.venv/bin/python scripts/browser_wikibooks.py \
  --base-url http://127.0.0.1:8001 \
  --source-bundle data/wikimedia/wikibooks-regex-266423 \
  --artifacts artifacts/wikibooks-browser
```

Нужны установленный Playwright Chromium и исходный runtime-пакет предыдущего
этапа. Скрипт сверяет SHA исходного wikitext/HTML с пакетом происхождения. Все
скриншоты и `report.json` записываются в игнорируемый `artifacts/`, книжный текст
не попадает в Git. Данные библиотеки читаются через реальный HTTP API.

Основные изображения: `wikibooks-credits-desktop.png`,

Читатель сохраняет текстовую проекцию таблиц, а не HTML-сетку; изображения и
формулы не добавлены этой проверкой. Снимки просмотрены: длинные строки
переносятся внутри страницы, содержимое кода и ячеек остаётся доступным.

Наблюдаемая граница native selection: у одного полного блока `DOM Range` сохранил
1291 символ, а `Selection.toString()` вернул 1290, исключив конечный LF. У двух
других блоков длины совпали. Поэтому проверка ручного копирования явно выбирает
внутренний текст без краевых разделительных LF и не объявляет побайтную
сохранность этих краёв стандартным выделением браузера. Все исходные краевые LF
проверены в DOM отдельно; кнопка «Копировать цитату» сохранила полный фрагмент и
ссылку точно. Подробные probes сохранены в `literal_clipboard` отчёта.

В конце проверки API по-прежнему показывал partial 1, RU 11 и нижнюю границу
полных подтверждённых произведений 24. Общий корпус параллельно продолжал расти,
поэтому его полный размер не зафиксирован как инвариант browser-теста.
